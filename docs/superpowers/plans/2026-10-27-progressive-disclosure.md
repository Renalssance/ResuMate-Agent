# 全界面渐进式披露开发计划

> **For agentic workers:** 使用 `executing-plans` 技能按任务实施；仅在用户明确选择委派时使用 `subagent-driven-development`。使用下方复选框记录进度，不因编写计划而开始实现。

**Goal:** 在保留 ResuMate 品牌和业务能力的前提下，使全部界面按“行动与判断 → 理解与编辑 → 追溯与配置”呈现信息，降低首次进入的信息负担。

**Architecture:** 复用现有 Vue 页面、原生 `details`、`dialog` 和页面局部状态，不新增 UI 框架、通用披露状态管理器或后端接口。简单内容用原生展开，互斥任务用视图切换，编辑继续复用现有草稿和保存流程。浏览器扩展维持原生 DOM 实现，单独交付和验证。

**Tech Stack:** Vue 3、TypeScript、Pinia、Vue Router、现有 CSS 变量与 Lucide 图标；扩展使用 JavaScript、Chrome Side Panel API 和现有中英文词典。

**Spec:** 本文第 2 节记录本轮全界面梳理的实施决策，作为本计划的需求基线；品牌依据为 [视觉语言 v1.1](../../design/visual-language.md)。讨论中的“可以考虑”不自动变为必须实现，取舍在覆盖表中明确。

**日期：** 2026-10-27。

**当前状态：** 仅计划；未修改产品代码，未运行产品验收。源码审查覆盖 10 个路由、9 个页面组件、12 个共享组件及扩展侧栏。实施前以工作区现状为准，不能把历史审查中的截图或测试结果当作本次证据。

## 1. 全局约束

- 遵守仓库 `AGENTS.md`；检查前明确具体失败及失败后的处理方式。
- 保留奶油底色、可可棕主操作、雾蓝辅助色与 Milo 品牌；不新增视觉主题。
- 保留现有路由、API、数据结构、认证、文档解析、匹配、试题、投递和填充业务语义。
- 不增加依赖、后端接口、特性开关、兼容框架、持久化展开偏好或哈希比较。
- 当前工作区已有大量未提交修改；不得重置、覆盖、整仓暂存或把其他任务改动纳入提交。
- 本轮不自动提交、合并、部署；如之后要求提交，按交付模块选择本次差异。
- 错误、风险摘要、必填输入、当前筛选条件、未保存状态、主要操作不隐藏在折叠内容里。
- 收起不清空输入，不改变对象选择，不重置勾选，不中断正在运行的任务。
- 详情关闭后返回触发位置；后台刷新不改变用户主动选择的展开状态。
- 原生 `details` 优先；需要受控展开时使用按钮、`aria-expanded`、`aria-controls` 和明确的目标区域。
- 字段及操作不能仅悬停可见；长文的完整内容必须支持点击、触屏和键盘访问。
- 进入抽屉或详情后通常最多再展开一层；不把每个短字段都做成折叠项。
- 不以隐藏内容冒充延迟请求或性能优化；本轮不改现有数据加载方式。

## 3. 文件和实现边界

所有路径相对仓库根目录。

- 共享视觉：`frontend/src/styles/main.css`，仅追加必要的披露摘要、正文与视图切换样式；品牌变量不重建。
- 页面状态：保留在各 `frontend/src/views/*.vue`，不引入全局 disclosure store。
- 进度与抽屉：只修改对应 `frontend/src/components/*.vue`，不改其既有 props 和事件契约。
- 外观：创建 `frontend/src/composables/useAppearance.ts`，仅统一原来全局布局与新设置入口共享的主题值及存储键。
- 扩展：修改 `extension/sidepanel/sidepanel.html`、`sidepanel.js`、`sidepanel.css` 和 `extension/lib/i18n.js`。
- 文档：更新 `docs/design/visual-language.md`，新建 `docs/design/progressive-disclosure-implementation-review.md` 记录实际完成和未验证边界。
- 不预先拆分大型页面、不新建万能 Disclosure 组件；发现具体重复逻辑时只抽取该职责。

## 4. 实施顺序与依赖

1. 任务 1 定义并落地通用披露外观。
2. 任务 2–4 完成进度、文档列表和详情。
3. 任务 5 完成结构资料，作为长表单的独立交付。
4. 任务 6–7 完成分析结果和投递工作台。
5. 任务 8–9 完成设置与全局入口，同一交付中避免出现两个外观开关或完全没有入口。
6. 任务 10–11 完成插件介绍与扩展侧栏，扩展作为单独可验收交付。
7. 任务 12 进行跨模块验收和规范收尾。

这是一份统一计划，不要求一次性上线所有模块；每个任务完成后其原有业务仍应可用。

## 6. 验证策略：失败必须对应处理动作

本计划是界面组织变更，原生开合和纯样式不新增镜像测试。状态保持、表单有效性和填充选择等行为用真实浏览器交互验证；若提取纯函数，才按现有 Node 测试风格增加针对该函数的行为测试。

| 检查 | 检测什么具体失败 | 失败后做什么 |
| --- | --- | --- |
| 实施前查看相关文件差异 | 工作区变更与计划基线不一致 | 调整任务，不覆盖既有改动 |
| `npm --prefix frontend run build` | Vue 模板、类型、CSS 或生产打包错误 | 修正对应模板/类型/样式，再重跑 |
| `npm --prefix frontend test` | 资料草稿、筛选、日程、导出等原有行为回归 | 定位相关变更；不删除有效断言 |
| `node --experimental-strip-types frontend/src/utils/taskProgressChart.test.ts` | 步骤呈现改动误伤已有进度语义 | 恢复真实任务状态与图表输入关系 |
| `node --experimental-strip-types frontend/src/utils/structuredDisplay.test.ts` | 若修改结构展示工具，丢失字段或分组内容 | 修复转换；未改工具则不必跑此项 |
| `node frontend/src/components/appLayoutFluidBackground.test.mjs` | 主题入口迁移误伤背景生命周期和偏好 | 按新职责更新定位断言，保留有效行为约束 |
| `node frontend/src/styles/glassEffects.test.mjs` | 共用样式改变正文表面和玻璃范围 | 修正样式覆盖，不恢复已废弃设计 |
| `node --check extension/sidepanel/sidepanel.js` | 扩展脚本语法错误 | 修正脚本后重新加载扩展 |
| `node --test extension/tests/auth.test.mjs extension/tests/i18n.test.mjs` | 账号流程或双语键回归 | 修复绑定、状态或词典 |
| 桌面 1440px、手机 390px 相关页面交互 | 开合、焦点、草稿、视图切换失效 | 修正具体容器/状态处理 |
| 长字段页 320px、200% 文字放大 | 内容裁切、横滚、操作不可达 | 修正换行、最小宽度、滚动容器 |
| 真实扩展 fixture 流程 | 勾选丢失、填充目标错误、底栏遮挡 | 修正 DOM 重绘或布局，不改变填充授权语义 |

### 浏览器验收用例

1. 文档：首次空列表、已有文档、上传中、部分解析失败、组合筛选、详情切换。
2. 任务：运行→成功、运行→失败、用户展开后收到新进度、批量任务部分结束。
3. 资料：缺失字段定位、新增条目自动展开、折叠保留草稿、失败保留、取消恢复、复制失败反馈。
4. 匹配：风险摘要不隐藏，评分与证据可达，关闭回到对应结果。
5. 试题：配置与历史切换、窄屏选集合、单题及追问展开。
6. 投递：带草稿切视图、选日期查看全部事件、完成日程、统计弹窗、时间线、导出。
7. 设置：隐藏无效参数可定位，清空密钥状态外显，配置失败与未配置区分，主题持久化。
8. 扩展：未登录、有缓存离线、扫描前、扫描后、取消勾选、切语言、资料切换需重扫、部分填充失败。
9. 不改页面：首页、登录、注册仅在共享 CSS 或布局影响到它们时做视觉回归，不重测无关后端流程。

每个用例记录预期、实际结果和使用的数据条件。若只能完成 API 拦截的浏览器验证，明确注明未验证真实后端；若不能加载真实扩展，注明未完成扩展验收，不用静态 HTML 截图替代。
