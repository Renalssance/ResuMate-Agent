# ResuMate AI 全栈与 Agent 开发范围

日期：2026-10-29。依据：本聊天中用户确认的四层能力与技术方向。本文件整理已确认范围及计划采用的实现边界，不代表功能已经实现。

## 目标

以前端为主线，建设覆盖浏览器基础、前端工程、业务后端、Agent 应用工程的求职工作台。Agent 使用 Deep Agents，在其基础上实现应用级 Harness 与任务评测；RAG 保留现有能力，暂不作为主要研发方向。

## 四层要求

1. HTML/CSS/JavaScript/TypeScript、语义化、键盘操作、响应式布局、浏览器文件与网络 API。
2. Vue 业务开发、状态与组件边界、工程化、流式交互、WebSocket 双向面试、网络恢复、前端性能、组件与端到端测试。
3. Python/FastAPI、API、数据库、鉴权、事务、异步任务、部署；重点体现工程化、网络、性能、安全。
4. Deep Agents、Tool Calling、应用级 Harness、上下文、业务记忆、SSE、可靠任务执行、可观测性与评测。

## 产品主流程

收藏岗位 → 关联个人经历和简历 → 匹配分析 → Agent 补问 → 生成修改建议 → 用户逐条审阅 → 保存版本并导出 → 关联投递 → 多轮面试准备与反馈。

## 已确定原则

- 保留 Vue 3 + TypeScript + Python/FastAPI；不新增 Java 服务作为本轮主线。
- Deep Agents 是主运行时；不再自写一套通用模型—工具循环。
- 应用级 Harness 管理 Run、工具边界、业务结果、恢复、事件与上下文策略。
- 业务服务是页面和 Agent 的共同写入入口，模型不能直接决定用户归属或绕过权限。
- 现有解析、匹配、投递、日程、扩展和视觉语言尽量复用。
- 安全与性能针对项目实际入口、真实负载和故障开展；不建设无业务依据的基础设施。
- RAG 不优先更换向量库，不建设复杂混合检索、知识图谱或检索平台。
- 不包含自动海投、自动发送邮件、支付、多租户组织管理、多机调度、任意代码执行平台。

## 计划的运行边界

首版支持本地开发和单机 Docker Compose；API 与 worker 分离。集成环境使用 MySQL、Redis 和一个 Agent worker；本地单人开发保留 SQLite。Graph checkpoint 使用官方 SQLite saver，保存在 worker 专属持久卷；只由该 worker 访问。该选择支持首版单执行器恢复，不宣称支持多机共享 checkpoint。

传统业务数据库保存 Run、事件、业务事实与产物；Redis 用于消息队列、跨进程限流、一次性 WebSocket 票据、事件唤醒和短期统计缓存，不作唯一事实源。WebSocket 承载文字模拟面试双向命令与反馈，SSE 保留用于单向长任务进度；不增加语音范围。现有 CloudBase 功能不主动移除；新的独立 worker 部署不冒称已适配 CloudBase。

## 成功定义

- 完整主流程可通过 UI 操作，键盘可达，错误有恢复路径。
- WebSocket 支持一次性票据鉴权、心跳、背压、命令去重、跨 API 重连和持久事件补发；Redis 通知丢失不能丢失已接受回答。
- 断开 SSE 不取消任务；重连和刷新可恢复状态；事件接口校验归属。
- Agent 可补问、暂停、继续、取消；worker 重启后能恢复已接受的工作，或明确提示无法恢复的原因。
- 对于创建草稿等业务写操作，重复执行不创建重复结果。
- 用户确认的事实与修改版本可追溯；生成材料不应无依据新增经历。
- 每次技术改进都有相应的测试或评测依据；性能数字来自记录了条件的真实测量。
