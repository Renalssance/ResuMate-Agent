## 浏览器覆盖的实际路径

1. 页面选择岗位/简历并创建任务，真实 worker 暂停；刷新后动作 ID 不变；键盘提交后生成一份产物。
2. 新页面打开测试入口已准备的真实暂停任务，回答并完成。
3. 两个标签页填写不同答案，A 先处理，B 的实际旧提交收到 409，文字保留。
4. 回答后离开页面，worker 继续运行；返回时能读取产物，没有隐式取消。
5. 等待补问时明确取消，最终无产物。
6. worker 执行中明确取消，最终停止且无产物。
7. 中断 SSE 网络，页面提示重连，SQL 中 Run 仍等待回答；恢复后提示消失并可继续完成。
8. 既有注册页的密码确认本地验证仍运行。

## 发现、修复与教学联系

- **状态与产物必须一起防止旧响应覆盖。** 只保护快照不足以阻止较慢的旧请求把新草稿替换为空；现在旧序号刷新整批丢弃，并覆盖反序完成测试。
- **等待中的重连也要更新连接状态。** 恢复网络后可能没有新事件；连接成功回调清除断线提示，并刷新新的服务端快照/产物。
- **取消后动作记录仍存在。** 服务端保留问题用于历史，页面不能据“存在动作”判断可提交；终态关闭提交入口，未提交文字只读保留。
- **实际截图发现的产品问题。** 详情子路径未激活左侧导航；部分材料字段露出英文键名；完成状态仍有“将继续处理”字样。沿用原导航活动样式、局部中文映射与准确提示修复，没有重做全局样式。
- **截图本身也可能不可信。** 在桌面切换手机尺寸后立刻全页截图，侧栏过渡和聚焦滚动会造成遮挡或标题裁切。测试改为等待响应式布局，使用实际关闭导航操作，回到页首后再截图；不注入样式隐藏实际问题。
- **测试登录触发真实限流。** 最初每用例重新登录会触发 5 次/分钟限制。改成每个 Playwright worker 登录一次，仍使用真实 Token，不关闭生产限流。
- **端口探测把 TIME_WAIT 误判为占用。** 测试入口探测使用地址复用以区分刚关闭的连接与真实监听，仍拒绝抢占已运行服务。资源清理只针对本次进程组与 Redis 容器。
- **独立审查发现时区缺失。** SQL 的 UTC 时间失去 tzinfo，直接输出会被浏览器当成本地时间。本人任务/产物响应补 UTC offset，并用实际响应断言回归。其余归属、补问、冲突、取消、订阅恢复及真实联调合同经审查正确。
