## 审查修复与测试环境调整

独立审查发现统计路由的原鉴权 Session 未释放；服务内部使用短 Session 并不能关闭路由已经持有的连接。定向测试真实执行 SQL 鉴权读取，在 Redis GET 边界断言请求 Session 已无事务；SQLite/MySQL 均先失败。修复为读取 user_id 与 session_factory、关闭请求 Session、再 await 缓存服务。两库相关测试与旧设置回归最终 22 passed。完整后端/浏览器运行启动于这次小修之前，最终记录需与该定向结果分开。

浏览器的 27 个场景共用同一合成用户，新增 run 10/60 配额后需要逐案隔离窗口。tests-only fixture 每案只删除该用户的 run 计数键，真实 limiter、Redis 和队列保持原样；没有生产关闭开关。服务使用独立环境频道前缀。

## 真实集成首次启动：环境失败

invocation `241c20c7e4984135b53338a248caa55f` 的当前镜像构建在 exporting/unpack 阶段遭遇 Docker containerd snapshot filesystem read-only；7 个测试均为 setup error，`executed:false`。API/MySQL 业务场景尚未启动，没有计入任何通过数。[首轮证据](raw/2026-10-30-t20/build-failed-241c20c7)保留构建日志与状态。

恢复后 Docker 可以写入。按精确名字删除本任务旧 `resumate-test-*` 镜像、失败的 T20 镜像和已确认未共享的本轮构建缓存，保留所有卷、T11 依赖底座与其他镜像；宿主空闲恢复约 3.5GiB。为避免再次耗尽空间，下一轮先核对 T11 镜像的已安装包与当前锁文件，再挂载完整当前 backend 源码开展验收。此路径符合计划中的依赖镜像复用边界；不能声称主 Dockerfile 新构建成功。
