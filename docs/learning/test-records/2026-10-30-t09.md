# T09 测试记录：固定输入与有来源的字段建议

日期：2026-10-30。基线 `948ae8a`，沿用已批准的独立工作区。讲解见[第九课](../09-evidence-based-tailoring.md)。

## 交付与验证目的

新 Run 保存简历/JD/确认事实/历史匹配的完整输入快照，公开 Run 输入仍为业务 ID。建议仅针对固定简历实际字段，带原文、改写、理由与来源；缺信息时 after=null。三类来源分别验证固定简历、固定事实、当前任务已回答动作。业务服务保存原始简历与 pending changes，不自动应用，不覆盖主简历。

检查首先针对真实失败：输入混入后来资料、requestId 假冲突、来源伪造或删除、重复写草稿、工具事件不一致、历史草稿缺失旧输入提示、页面来源错误及手机长文溢出。失败后修对应快照/事务/归属/显示实现，不扩张成通用版本框架。

## 审查与实际截图发现

独立审查发现 T08 已有旧格式草稿提前返回，导致原资料变化后 basedOnOldInput 仍为 false。旧格式只是缺逐条来源，并不缺 Run 的版本信息；把漂移比较移到早返回前，sources 继续为空。两库红测 2 failed；修复后旧草稿变化、资料删除历史可读 4 passed。没有伪造旧来源正文。

该改动触发已有有界查询检查：五个产物逐项比较当前输入会重复查询。用一次 Run 输入比较结果供同一列表复用；测试保留 auth、Run、versions、resume、JD、facts 共最多 6 次查询的固定上限。旧 fixture 补当时真实时间戳，符合 T08 产物。两库先 2 failed / 20 passed；最终完整回归包含修复。独立审查只复查这两处变更，发现已关闭。

## 真实联调场景

测试使用真实 HTTP、独立 Celery worker、临时 SQL/checkpoint 与 Redis；仅外部模型为确定性 fixture。先保存已确认事实，创建任务并等待补问，在另一请求修改主简历，再通过真实页面回答。worker 仍按固定旧原文产生两条建议：一条带原简历/确认事实/补充回答来源，一条因缺指标而 after=null。验证 API 与页面旧资料提示、来源正文、刷新后一份产物，以及原简历不被生成流程覆盖。
