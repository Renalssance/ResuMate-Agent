## 四个真实进程中断

使用 Linux 容器内的同一 SQL/checkpoint，Redis 与实际调度器；worker stale 90秒、scanner 15秒没有为了测试缩短。通过SIGKILL与退出码137确认真实终止，不手动改数据库推进状态。

1. 模型返回前：已通过，attempt/epoch 1/1→2/2；模型开始数1→4，最终1草稿/1操作/1产物事件。
2. 草稿提交后：已通过，attempt/epoch 1/1→2/2；开始数2→3，草稿ID/内容与成功操作保留，均只有1行。
3. checkpoint完成后、Run终态前：已通过，原checkpoint.next为空；开始数3→3，恢复只收敛最终状态，草稿/操作不变。
4. 回答提交后、API发布前：首轮已通过，SQL中answer/action已提交、Run queued；API在发布前被SIGKILL。scanner继续原回答，attempt1/epoch2，模型开始数2→5，回答/action引用保持唯一。
