# T08 测试记录：岗位中心与可追溯事实

日期：2026-10-30。基线提交 `9b4ea1f`；独立工作区与 `codex/resumate-fullstack-learning` 分支延续 T07。教学讲解见[第八课](../08-jobs-and-confirmed-facts.md)，合同见[T08 局部计划](../../superpowers/plans/2026-10-30-t08-jobs-and-facts.md)。

## 本单元结果

岗位中心复用 JobDescription，支持粘贴收藏、来源、重复识别、搜索/状态/分页、主简历关联、真实文本解析、历史匹配和匹配/材料跳转。事实支持用户明确确认、未确认保存、追加修改版本、删除版本和历史；新 Run 固定本人、适用简历的当前确认版本。

保留旧资料与接口。粘贴岗位在文档管理中重新解析时走相同原文路径，不伪造文件或向量成功状态。删除来源简历时同事务撤回对应当前事实，避免它们因外键清空而进入其他简历任务。

## 检查目的与实际结果

- 岗位接口/迁移检查：检测重复收藏覆盖原编辑、跨用户关联、分页不稳定、粘贴解析找不到文件、MySQL 升级破坏旧记录。失败时修对应查询、归属、解析入口和增量 SQL。最终 **43 passed，5.95s**，含 SQLite/MySQL 岗位 30 项与原文档回归 13 项。
- 事实与 Run 定向检查：检测旧版本复活、并发覆盖、任务混入新事实、草稿引用任务外事实。最终 **98 passed / 1 skipped，16.89s**；MySQL 的 skip 是仅针对 SQLite 行锁缺失的旧用例。
- 审查发现的来源删除回归：真实 HTTP 删除简历 A 后，为 B 创建 Run；修复前 SQLite/MySQL **2 failed**，修复后相关 **10 passed**，验证历史保留、未确认也撤回、旧删除版本不重复追加。
- 完整后端回归：检测数据列、事实输入和文档操作对原有解析/匹配/任务的破坏。**442 passed / 2 skipped，38.43s**。使用真实临时 MySQL socket，每例独立随机数据库。另一项 skip 为默认不启用的 Compose 崩溃实验，本单元未修改 worker 恢复逻辑，T06 既有通过证据沿用。
- 完整前端单元：检测来源选择/明确确认、编辑后取消确认、409 输入保留、跳转预选、账号切换迟到响应、筛选 URL 与错误展示。**63 passed / 16 files，2.17s**。随后新增失败后标题/列表刷新回归，受影响 JobsView **4 passed**；最终构建通过，**1.51s**。
- 真实浏览器检查：运行完整 T07 + T08 场景，检测真实 HTTP、独立 worker 和界面合同；最终结果与输出见下方封存记录。

8 条后端警告来自已有 SWIG、FastAPI on_event 与 utcnow 弃用。前端主包 747.14 kB，保留大包提示；后续 T17 测量后优化。本单元没有调用付费模型，也未上传真实简历。

## 实施与失败记录

1. 缺功能的测试先失败：岗位最初 26 失败，事实接口最初 24 失败；实现接口后，事实运行测试仍有 8 个失败，明确暴露未固定事实集合、动态读取新版和草稿引用过宽。
2. MySQL DATETIME 写入精度与内存值不同，导致写响应和历史响应不一致；提交后刷新再序列化数据库实际值。
3. 普通 URL 大小写路径被 MySQL 默认比较规则混淆，导致错误去重；精确正文和 URL 比较局部使用二进制排序规则，真实两库用例回归。
4. 文档库已有“重新解析”入口也会遇到粘贴岗位。补无文件分支调用相同文本解析，返回 vectorized=false，避免新页面可用而旧入口失效。
5. 首轮真实浏览器看到岗位列表 422，原因是“全部状态”传了空字符串；省略空参数。截图中 `[object Object]` 暴露真实错误数组格式化缺失，改为可读消息并保留 HTTP 状态。
6. 首轮测试的精确 getByLabel 匹配遇到旧 label 包裹 select 的 option 文本，未找到实际存在的控件。实际可访问树里 combobox/listbox 名称和预选正确，测试改按角色与名称定位，没有修改产品来迎合错误定位。
7. 事实 UI 最初强制每次保存都勾选确认，与 confirmed:false 合同不一致。允许保存未确认内容；编辑后确认默认清除，避免旧确认自动继承到新文字。
8. 账号切换后旧文档列表响应可能回填。文档 store 接受响应前比较实际访问令牌；延迟请求/错误用例先红后绿，范围只覆盖本次预选依赖的列表读取。
9. 独立审查发现来源删除会把局部事实变成全局事实。追加 tombstone 后再删除来源，保持同一 SQL 事务；审查的其他版本、冻结引用、岗位解析与迁移逻辑正确。
10. 实际错误截图显示解析失败后步骤仍“进行中”，标题/列表仍“待解析”，原始供应商错误重复出现。页面失败回调设置真实失败进度并重读岗位状态；中文说明保留原文与重试提示，原始详情折叠。修复有真实进度组件回归，截图重新查看。

## 浏览器数据与环境

沿用 T07 一次性 SQL/checkpoint、Redis 容器、真实 API 与独立 Celery worker。T08 的测试 API 入口只把 AgentHarness 使用的外部 OpenAI HTTP transport 替换为确定性回复；真实客户端、schema、进度、用量、SQL 与异步响应均保留。合成模型失败一次后可重试，用于检查真实错误路径。

新增三条业务流程：

- 收藏长岗位原文 → 关联主简历 → 后台解析 → 匹配页预选 → 材料页预选 → 新 Run 补问 → 独立 worker 生成一份草稿。
- 从简历选实际经历（尚未确认） → 明确确认保存 v1 → 修改并保存未确认 v2 → 查历史 → 删除 v3 → 显示已删除记录。
- 真实解析调用失败 → 原文仍在 → 界面重试成功 → 筛选无结果空状态。

岗位页按 1440px 桌面、390px 手机捕获真实页面；事实卡片按相同视口捕获实际组件区域，避免整个长资料表缩小后文字无法阅读。后续回归截图写入 test-results，验收后复制到本单元资产目录，不再覆盖 T07 已封存图片。
