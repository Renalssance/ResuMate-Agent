# 第18课：把边界落在真正执行工作的地方

本单元沿用已经工作的账号所有权、人工确认和Redis限流。目标不是再造一套安全框架，而是找出当前支持路径真正能触发的问题，先复现，再修复，并分清产品缺陷、测试夹具问题和仍未验证的边界。

## 1. 限制应覆盖整个操作

原PDF页数限制只在OCR路径生效，101页可直接提取文字的PDF仍会进入处理。现在文件打开后立即检查总页数：100页可以继续，101页在逐页提取前被拒绝。原10MiB分块上传限制与失败清理保留。

更关键的是120秒解析上限。`Future.result(timeout=120)`只停止调用方等待，后台线程可能继续占用worker、调用模型甚至写数据库。因此文档解析改用专用子进程，父worker保留原执行锁与心跳；超时先kill/wait回收子进程，再按原epoch将Run标记为`document_parse_timeout`。这一预算包含提取、OCR、模型和embedding。

父worker被SIGKILL时无法执行finally。子进程从父进程持有的stdin管道监测EOF，在父进程消失后退出；恢复扫描仍使用既有SQL epoch和执行锁。真实进程测试分别阻塞提取、模型、embedding，验证没有成功产物、没有继续写入，并且下一任务能执行。另有父进程死亡后的恢复测试。这里验证的是本机OS进程与双数据库，不将它写成新Docker集成结果。

集成浏览器还暴露了正常退出问题：监视线程中的`sys.stdin.buffer.read()`持有Python缓冲锁，解释器关闭时可能异常终止。原测试只验证SQL成功，没有断言子进程exit0；新增两项先失败，再改用`os.read(fd,1)`检测EOF，正常退出与父死四项通过。“业务已提交”和“进程正常结束”是不同验收点。同轮上传失败另有测试夹具重复注入`http_client`的TypeError，不能混写成上述生产缺陷的结果。

拆出进程还改变了资源生命周期：它需要自己初始化、关闭已有同步Redis资源，否则模型用量提交后的缓存失效会退化到TTL。这个遗漏也先出现测试失败再修复。

## 2. HTTP超时与重定向要作用在实际客户端

新图原本已有账号请求超时，旧聊天与旧工具没有完整传入；远程embedding沿用SDK较长默认值。现在三个ChatOpenAI入口和Harness使用账号超时，embedding请求为30秒且不在SDK内部自动重试。文档尝试的120秒墙钟上限仍独立生效。

所有实际OpenAI兼容模型客户端，包括live评测的sync/async客户端，显式关闭重定向。HTTPX通常会在跨来源重定向时去掉Authorization，不能笼统声称所有跨域跳转都会泄密；但本项目要求调用者配置明确端点，模型客户端不应该自行向跳转目标继续发送请求。同源307、跨源308分别通过实际SDK和合成HTTP响应验证：跳转目标收到零请求，原请求保留指定超时。

测试不需要真实API Key，不需要花钱探测供应商。它验证传输行为，而真实模型协议和质量仍属于live评测。

独立审查还发现了这次修改带来的资源生命周期回归：显式传入普通DefaultHttpxClient之后，SDK不会再为它套默认自动释放wrapper。响应体正确关闭，不等于底层连接池会随模型对象释放。真实旧聊天正常结束与浏览器断开两条路径，均先确认图回调已结束、对象无剩余引用，再观察transport.close/aclose；原来两者调用次数都是0。新增正式测试得到4 failed/2 passed，其中已有显式close的两项本来正确。

修复只增加`backend/model_transport.py`中的两个小类型，恢复上游同样的同步close和运行中事件循环上的异步aclose回收语义，各使用点仍显式禁止重定向；不建立新连接池或改写图接口。生命周期与真实307/308传输共26项通过。这里保证的是对象回收时恢复SDK原有关闭行为，不承诺每次请求结束都立即销毁客户端，也没有把未发生的连接耗尽写成实测事故。

## 3. 日志保留排错信息，而不复制材料

旧日志直接记录完整prompt、response和异常堆栈，旧聊天也会把异常原文发到SSE。供应商错误体可能包含请求信息，因此这些通路改为记录模型、任务、尝试次数、时长、字符数、错误类型及必要HTTP状态。验证错误记录数量，不复制可能带原始输入的完整错误对象。

模型异常的原始文本不再进入Harness进度、反思提示、旧工具返回或聊天SSE。合成secret通过实际异常处理路径，测试同时检查日志、事件和下一次提示。业务材料仍存放于有归属控制的业务记录，不能用“删除日志内容”代替正确的业务存储。

## 4. Web入口的防护各有职责

- CORS采用明确本地origin默认值，去掉配置空格，拒绝`*`；Bearer请求不需要凭据Cookie模式。真实预检测试覆盖允许与拒绝的来源。
- 当前Vue页面按文本渲染，没有启用原始HTML Markdown。PDF模板转义、浏览器扩展消息限制已经具备，不为未使用的旧静态脚本增加处理层。
- 投递记录允许保存外部岗位地址，但页面只渲染http(s)链接，保留安全的打开方式。测试先证明javascript/data地址原来确实会生成链接，再证明修复与合法地址均有效。
- 生产nginx提供同源CSP，并为长任务SSE关闭缓冲。前端页面、API、PDF下载和截图的实际浏览器验证单独记录；仅写一个CSP字符串不算验收。

## 5. 工具权限不依赖模型听话

合成恶意JD要求删除资料、提交他人事实或读取宿主秘密文件。受控模型实际尝试这些操作，真实图和工具边界拒绝：删除工具没有暴露，他人fact无法写入，StateBackend文件工具不能读取宿主文件。双库六案验证业务没有被修改、秘密和他人内容没有进入模型请求或事件。

这些测试说明机械权限边界有效，不能被写成“真实模型安全率100%”。原所有权、人工确认、PDF转义与Redis限流回归也不算本单元新造的功能。
