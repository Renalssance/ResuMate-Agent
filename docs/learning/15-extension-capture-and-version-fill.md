# 第十五课：浏览器扩展的采集、认证与版本边界

本课对应 T15，已完成确定性验收；实际完成状态、命令与截图以 [测试记录](test-records/2026-10-30-t15.md) 为准。局部合同见 [T15 计划](../superpowers/plans/2026-10-30-t15-extension-capture.md)。本文连同原始日志记录实现、失败修复、最终浏览器与原生侧栏截图验收。

## 从用户动作确定边界

浏览器扩展已经能够选择原简历、扫描表单、逐字段勾选并填入。因此这次增加主动收藏岗位和已确认版本，并保留人工预览与提交。收藏、扫描、填入、实际投递是四个不同动作：保存岗位不启动模型，扫描不改网页，填入不点击提交，填表成功也不代表已经投递。

采集由用户点击发起。内容脚本优先读取主内容区域，过滤隐藏节点、导航、页脚与表单控件；侧栏展示可编辑的标题、公司、来源 URL 和正文，再由用户点击保存。无法注入的页面提供手动粘贴路径。切换页面或标签后清掉旧预览，避免把上一页正文和当前来源拼成一个岗位。

## 同一浏览器里有不同执行环境

```text
招聘网页 DOM ← 内容脚本：只读可见岗位、扫描或填入选择的字段
                       ↑ 固定的扩展消息
侧栏：预览与用户操作 → 扩展 service worker → 已配置的后端 API
                       ↓
                 认证与本账号存储
```

内容脚本能看到页面，并不应该同时拥有任意后端请求能力。固定消息类型描述业务动作，例如读取当前页、收藏岗位、读取档案、匹配字段；不接受网页传来的任意 URL、headers 和 HTTP method。后台核对发送者属于本扩展的侧栏页面，再读自己的后端设置与认证。

Chrome 的 `storage.local` 默认可由内容脚本访问，所以仅把 token 的变量搬进 worker 还不够；初始化将访问范围设为 `TRUSTED_CONTEXTS`。这使用已有 storage 权限，不新增浏览器权限。侧栏接收的是登录状态和用户名，消息响应不返回 token。[Chrome storage 文档](https://developer.chrome.com/docs/extensions/reference/api/storage#type-AccessLevel)

一次异步后台请求还需要保持消息通道，直到返回结果。实现依照固定 `{ok,data}` / `{ok:false,error}` 响应处理错误与 401，不把不同消息变成任意请求代理。[Chrome 消息传递文档](https://developer.chrome.com/docs/extensions/develop/concepts/messaging)

退出、换后端或当前账号返回 401 时清掉缓存与已扫描字段；普通网络故障才保留当前账号缓存供离线使用。异步请求还可能晚到：A 账号开始请求后切到 B，A 的档案响应不能替换 B 的列表，A 的 401 也不能退出 B。实现沿用请求发起时的账号与后端身份作判断，定向测试覆盖真实后台监听器和侧栏事件处理，不另造一套缓存框架。

## 为什么保留两个具体业务入口

原 `POST /api/jobs` 导入已经支持“同 URL、不同正文”作为不同输入，旧测试明确记录了这一行为。主动收藏的用户预期则是“同来源岗位已收藏”：网页文案更新后再点击，不应覆盖主应用中整理过的岗位或创建重复项。

因此增加明确的 `POST /api/jobs/capture` 收藏入口，复用输入模型、保存与返回结构。仅收藏入口在 URL 来源分支按完整 URL 找本人已有岗位；保留原导入的 URL 与正文规则，也保留显式 `sourceSite` / `sourceJobId` 的来源身份规则。没有 URL 时沿用正文去重。不同账号独立，URL 的查询参数、片段和大小写不被泛化删除。这是根据既有行为修订局部规划，不是在所有旧入口中悄悄换规则。

这里验证顺序重采集，不声称已经解决并发唯一或历史重复合并。数据身份足够时不新增内容哈希、站点适配平台或迁移框架。后端定向测试先在 SQLite 与 MySQL 上观察到缺少入口的 405，再验证新旧入口各自的行为。

## 已确认版本是不可变内容

原简历是一份可能继续编辑的资料；已确认版本是 T10 建立的冻结内容。档案列表现在区分原简历与已确认版本，返回 `sourceKind`、`resumeVersionId`、`revision`、`jdId` 等元数据。版本使用现有 `version:<id>` 标识，列表中的时间来自版本创建时间，界面也应显示为创建时间。

填表选择版本后，服务端校验本人归属与 confirmed 状态，并从版本内容生成字段，不能再读最新主简历来替换它。本人草稿直接请求返回 409，他人或不存在的版本返回 404；草稿不进入可选列表。源简历删除后，已确认版本仍能按冻结内容提供字段。

映射代码还需区别“字段不存在”和“本人明确清空”。如果用户确认把经历描述改成空串，`description or old_bullets` 会重新填回旧内容；同样，明确清空 `self_summary` 后不能回退旧的 `summary`。普通真值判断会在这里破坏用户决定，应按已确认的编辑与键是否存在判断。HTTP 双库测试覆盖这些内容，而不是只对纯映射函数传入一个理想对象。

在线匹配优先使用 `profileId` 由服务端读取内容，即使请求同时带了另一份 `profile`，也不能替换所选版本。旧的仅传 `profile` 的接口用法继续保留。版本选择变化后旧扫描立即失效，重新扫描再允许填入；暂时离线使用明确标示的本账号缓存。

真实联调还发现一个小而具体的接口错误：`sourceResumeId` 是 `resume:1` 这样的标识，直接 `Number(sourceResumeId)` 得不到可用的主简历 ID，导致收藏时遗漏可选关联。修复读取前缀后的正整数；版本的源简历已删除时省略关联。三个定向用例分别覆盖原简历、版本与源删除，不改变冻结内容的读取方式。

## 表单文字的范围会改变匹配结果

第一次真实版本填表停在“填入”按钮不可用。诊断不是“没检测到字段”，而是检测到 9 个字段、匹配 0 个、阻止 9 个。每个字段的附近文本都带上了整个 form 的标签，其中包括“验证码”，于是敏感字段规则正确地阻止了错误的输入描述。

问题在文字提取范围：向父节点查找附近文本时，跨进了包含其他控件的共享容器。修复在到达这种容器时停止上爬，让姓名、工作职责保留自己的语义；验证码仍按原规则阻止。新增测试使用实际申请页的 DOM，先复现整张表单文字污染，再验证普通字段能匹配且只阻止真正的验证码。不能为了让按钮亮起来而放宽敏感字段规则。

这个案例说明：后端匹配规则、内容提取、字段渲染各自测试通过，仍可能在组合后传递错误语义。浏览器诊断给出了真实 DOM 与阻止原因，随后用范围明确的回归测试固定根因。该修复的定向测试和扩展全量测试已通过，真实浏览器重跑仍需单独记录。

## 为什么扩展测试不能只 mock Chrome

Node 测试适合检查消息来源、缓存清理、采集过滤与选择失效，但不能证明 MV3 worker 能启动、消息发送者字段正确、页面脚本实际注入或侧栏布局正常。双库 HTTP 测试证明接口与保存行为，也不能替代这些浏览器事实。

真实浏览器验收使用 Playwright 自带的 Chromium 和临时持久配置，实际加载解压后的扩展包，连接真实 API/SQL。测试页与外部模型响应是受控 fixture，不调用付费模型；扩展消息、脚本注入、认证与业务保存仍走真实实现。扩展页面截图明确称为扩展页面，原生侧栏另行观察；不把网页模拟 Chrome 对象当成完整扩展验收，也不使用日常浏览器账户。[Playwright 扩展测试文档](https://playwright.dev/docs/chrome-extensions)

测试准备也会失败，需要与产品问题区分。首次四项包验收中，收藏通过，版本扫描失败，后两项被连续登录触发的 5 次 / 60 秒限制阻断。修正是复用后端真实签发的 token，并保留收藏案例的完整 UI 登录，不关闭认证限制。另一次版本选择等待失败，源于测试在侧栏载入列表后才创建版本；创建后明确刷新列表即可，不能据此宣称产品不支持版本。

截图需要打开查看：320px 与 390px 宽度下，长网址、正文、版本标签、按钮换行、错误与已收藏状态都应与既有米色/棕色视觉一致。已打开的手机说明页暴露了单行省略号截断；自然换行修复完成后仍要重新看图。页面测试通过和构建通过，不能证明视觉修复已经验收。

表单 fixture 记录 submit 点击和提交次数；最终浏览器应同时验证选中字段写入、未选字段与验证码不变、两种提交计数均为 0。当前记录不能用未走到的断言宣称这条链路已经通过。

## 学习练习

1. 将同一岗位页正文改一行再收藏，解释为什么返回原岗位，但原导入接口仍可保存新输入。
2. 确认一个不同于主简历的经历描述，用它填表，再读取主简历，比较两个内容的来源。
3. 明确清空版本中的经历描述，解释为什么不能用 `or` 回退旧内容。
4. 取消勾选姓名后填入，观察姓名、验证码、工作描述及 submit 计数。
5. 检查一个字段的附近文本，解释为什么共享容器中的验证码会影响普通姓名字段。
6. 退出 A 后登录 B，让 A 的请求最后返回，说明哪些结果应被丢弃，以及为什么普通断网仍可以保留 B 的缓存。
